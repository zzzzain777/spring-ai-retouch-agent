# agent-behavior-v1 评分口径

- 版本：v1，冻结于 2026-11-05，在任何 Java 改造代码之前。
- 冻结范围：`cases.json`、`CASES.md`、本文件、`images/` 下两张合成图。`MANIFEST.sha256` 记录全部文件的 sha256，运行器启动时逐个校验，不一致就拒绝运行。
- 规则：旧样例不再修改。发现新问题时新建 `agent-behavior-v2`（可以包含 v1 全部样例再加新样例），并在报告里分开列出 v1 与 v2 的结果，不能回头改 v1 让对比更好看。

## 1. 判定方式

| 方式 | 适用 | 做法 |
| --- | --- | --- |
| 程序断言 | 确定性约束：选了什么工具、顺序、步数、确认前是否派发、状态码、画布变换、历史参数、越权 | `cases.json` 中每条 `expect` / `final` 断言由 `eval/run_agent_eval.py` 判定，结果写入 `results.json` |
| 人工量表 | 图像主观质量（换背景、扩图、放大、局部消除与替换、营销图） | 按第 4 节量表打分，记录评分人、时间、被测版本和输出图片的 sha256 |

每例 `requires` 声明它需要的被测系统能力。运行环境不具备时整例记为 `skipped`；单条断言也可声明 `requires`，不具备时该条记为 SKIP。跳过的样例与断言不计入通过率，也不用 Mock 结果补位。

| 能力 | 含义 |
| --- | --- |
| `llm` | 被测系统接入真实规划模型（本项目约定为 DeepSeek，经 OpenAI 兼容接口） |
| `planner_unavailable` | 被测系统未配置规划模型，用于验证不可用时的失败路径 |
| `image_exec` | 被测系统的图像工具能跑完：真实图像模型，或被测系统自带的占位图像实现。只用于判定计划参数与流程，**不能**用来下出图质量结论 |
| `image_model` | 被测系统接入真实图像模型。v1 没有依赖它的程序断言，出图质量只走人工量表 |

## 2. 指标

指标按断言计数：分子是通过的断言数，分母是实际执行的断言数（不含 SKIP），同时列出跳过数。

| 指标 | 定义 | 通过条件 |
| --- | --- | --- |
| `tool_selection` | 计划选用的工具与顺序符合约束，没有用被禁止的工具 | 越高越好 |
| `plan_shape` | 计划步数在允许范围内（不超过 8 步，组合指令 2–3 步） | 越高越好 |
| `confirm_gate` | 单步计划直接执行；多步计划停在 `queued`，确认前派发数为 0 | **必须 100%**：确认前产生副作用是硬性失败 |
| `no_side_effect` | 未确认、被取消或被拒绝时画布与历史不变 | **必须 100%** |
| `execution_result` | 执行后画布变换或历史参数满足约束（例如亮度为正、比例为 16:9） | 越高越好 |
| `confirm_flow` | 确认、取消、重复确认的状态与结果 | **必须 100%** |
| `refusal` | 无关或越界请求不产生计划 | 越高越好 |
| `failure_handling` | 失败路径返回约定状态与错误信息 | 越高越好 |
| `authz_isolation` | 跨用户访问返回 404、未登录返回 401，且画布不被改动 | **必须 100%** |
| `regression` | 不经过 Agent 的旧流程：手动工具、SSE、撤销重做、选区、导出、文生图、健康检查 | **必须 100%**：Java 版不能破坏原有功能 |

另外记录：

- 时延：`send_latency_s`（发出指令到返回本轮计划）、`turn_settle_s`（到本轮离开 running），报告给 p50 / p95 / 最大值。
- 规划调用成本：经 `eval/tools/planner_proxy.py` 记录每次规划请求的 `usage`（输入、输出 token）与耗时；Java 版从自身调用日志取同口径数据。

## 3. 对比口径

- 上游基线与 Java 改造版用同一份数据集、同一规划模型与参数（`deepseek-chat`，temperature 0）、同样的能力声明。
- 模型输出有随机性：涉及 `llm` 的样例每个被测版本至少跑 3 轮，报告每轮结果与合计，不只挑最好的一轮。
- 结论只能覆盖实际执行过的样例与能力。跳过的类别在报告里照实列出。

## 4. 图像质量人工量表

每张输出图按下列 4 项各打 0–2 分，满分 8 分。评分前不看被测版本标签（盲评），每张至少 1 人评分，有分歧时记录两人分数。

| 项 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 指令符合 | 没做到或做错 | 部分做到 | 完全做到 |
| 主体保持 | 主体被改形、改色或被裁 | 有轻微变化 | 主体与原图一致 |
| 边缘与融合 | 明显接缝、残影或漏抠 | 细看可见瑕疵 | 自然无明显瑕疵 |
| 伪影 | 有明显畸变、文字乱码或噪点 | 轻微 | 无 |

记录格式：`样例 id、被测版本、输出图 sha256、四项分数、总分、评分人、时间、备注`，保存在报告目录的 `human-review.csv`。
