# 研发流程与架构：入口索引

此文件对应视频示例中的总览文档，只做导航；详细事实分别由下列文件维护，避免两套架构描述漂移。

1. **项目目标与范围**：`requirements/product-prd.md`；进行中的 C 阶段见 `requirements/c-stage-prd.md`。
2. **业务行为**：`business-rules.md`，包括计划确认、工具、会话、选区、任务、权限与评测硬门。
3. **架构与数据权威**：仓库已有 `architecture.md`；`architecture-addendum.md` 解释视频示例与 Java/React/Python 现状的对应。
4. **接口**：`api-contract.md`；字段与错误码以控制器、DTO 和测试为准。
5. **开发方法**：`development-workflow.md`；当前任务见 `tasks/c-stage-tasks.md`；完成后按 `reviews/c-stage-review.md` 审查。
6. **环境与部署**：`deployment.md`；本机实际运行以各服务 README 与根目录 `docker-compose.yml` 核对。
7. **事实与证据**：仓库已有 `project-state.md`、`claim-ledger.md`、`upstream-baseline.md`，评测数据与报告见 `eval/`。

本项目在 C 阶段中途引入这套文档流程。既有代码和报告的完成时间以提交和运行记录为准，不能从新文档的创建时间倒推开发历史。
